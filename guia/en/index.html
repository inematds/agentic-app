In short

agentic-app is a Python framework for companies to build AI apps starting from a business outcome, not from the agent. It is for anyone who needs to put AI inside a real process (HR, people management, support) with control: the LLM runs inside a fixed workflow, every external action waits for human approval, rules with numbers become tested code and every run is recorded. It ships with a complete example app (manager coaching) and runs with just Python 3 installed, no key and no internet.

What it is

An app built around a decision, not a chat built around everything

The starting question is not "which agent do we build?". It is "who decides what, and how do we measure whether it got better?". The agent comes later, as one piece of the process.

🧱 Workflow before agent

Each LLM use is one node among four others: context, code, condition and formatting. Same input, same output.

✋ Nothing sends itself

The workflow only proposes. The email waits in the queue until the person reads, edits and approves it. Everything goes to the audit log.

📏 A rule with a number is code

The vacation manual becomes functions with strict input and 13 policy tests. Change one number, a test breaks.

How it works

A fixed path, with the LLM in a single box

The engine checks who asked, assumes the workflow identity, validates the input and runs the nodes in order. The output is validated JSON. Actions become proposals. One audit line per run.

Trigger→ Role allowed to run?→ Context→ Code→ Condition→ LLM→ Formatting + schema→ Proposal in queue→ Person approves→ Runs + audit

HR assistant, node by node

profile (context, identity svc-rh) → category (LLM classifies: vacation, parental leave or other) → condition → data (code pulls the numbers out of the question) → agent (LLM chooses among the tools of THAT policy only) → explanation (code) → formatting.

Goal follow-up, node by node

team (context) → overdue goals (code) → any pending? (condition) → drafts (LLM writes one per person) → formatting validates and proposes 6 emails. None goes out before approval.

Usage guide · step by step

From clone to your first app

The first four steps run the example. The others show what you swap for your company. The full walkthrough, with a rollout checklist, is in docs/PASSO-A-PASSO.md (in Portuguese).

1

Download and run the tests

48 checks, no network. The last line must be OK.

git clone https://github.com/inematds/agentic-app
cd agentic-app
bash tests/run.sh          # 48 checks, 0 failures → OK
2

Run the demo in the terminal

Runs the 5 workflows: RBAC denying, drafts, approval with editing, HR assistant, the Monday 08:00 scheduled run, the email-received event and the report.

python3 -m agentic_app.demo
# generates saida/relatorio.html, saida/relatorio.pdf, saida/audit.jsonl
3

Open the panel

Switch person at the top (manager, HR, employee) and see what each role can do.

python3 -m agentic_app.serve --porta 8765
# http://127.0.0.1:8765  (only on your machine)
4

Prove that policy is code

The script changes nine numbers in the manual, one at a time, and checks that some test breaks.

bash tests/prova_mutacao.sh  # 9× "quebrou (bom)" → OK
5

Fill in the outcome canvas

The user, the decision, today's cost and a success number with a deadline. No metric, no start.

cp templates/canvas-resultado.md docs/meu-canvas.md
6

Encode your policy with tests

One constant per number in the document, one test per limit (the exact value and its neighbor).

cp templates/politica_modelo.py agentic_app/policies/reembolso.py
cp templates/test_politica_modelo.py tests/test_reembolso.py
7

Design the workflow in JSON

Context → code → condition → LLM → formatting. The external action goes in propor_acao, with the editable fields.

cp templates/workflow-modelo.json agentic_app/apps/coaching/workflows/meu_workflow.json
python3 -c "from agentic_app.workflow import carregar_spec as c; c('agentic_app/apps/coaching/workflows/meu_workflow.json')"
8

Define roles, identities and approvers

Who runs each workflow, which service account it acts as and who approves what it proposes.

cat templates/permissoes.json
9

Swap the LLM when the process is ready

The fake stays in the tests. For a local model, one variable. For another provider, a subclass of LLM.

AGENTIC_LLM=ollama python3 -m agentic_app.demo
